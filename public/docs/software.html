The big picture

LETZZ is a family of two product applications that help a person keep sensitive life documents under their control, and help regulated organisations request only what they need - with a clear audit trail of consent.

  • LETZZ Wallet is for the individual (the data subject). On phone it is the vault and biometric release surface. On web it is a Wallet Subject desk for requests, hashes, packages, and assistance.
  • LETZZ Platform is for obliged entities (banks, fintechs, and similar organisations that must run KYC and AML checks). Staff work cases, organisations, screening queues, document requests, and grants.

Platform Owner monitoring exists as infrastructure for operators. It is not offered as a third peer product in this partner hub.

Five distinct states (never mixed)

Everyday language often collapses “sent,” “approved,” and “cleared” into one idea. LETZZ keeps five meanings separate so auditors, staff, and individuals can trust what each screen is saying.

State Plain meaning Common mistake to avoid
Delivery A request or package reached the other side. Treating delivery as approval.
Consent The person agreed to a scope of sharing. Assuming consent lasts forever for every field.
Grant Access was issued for a defined pack or hash set. Equating grant with download of original bytes.
Verification Integrity or identity checks completed as designed. Calling verification a legal certification.
Clearance Staff tier may view, download, or approve under policy. Letting any staff member see every document.

What the Wallet does

The Wallet is the individual’s document concierge and control surface. Value compounds as the person stores more of their life materials and answers organisation requests without losing ownership of the vault.

Documents and packages Catalogue hashes, group stacks, prepare response packs for requests.
Home and inbox See pending organisation requests; grant or decline with a clear outcome.
AI Concierge (Wallet only) Local light help free; heavier analysis is a paywalled server path when entitled. Never an OE product.
Data Subject module Locally indexed life store with read-only source grants the person controls.
Guest one-time share Share selected items with someone who does not yet have the app, with a registration invitation.
Device-bound release Outbound responses are meant to pass a face check tied to one device key on phone.
Hash-first honesty. In the current product model, Platform receives cryptographic hashes and structured grants by default. Original document bytes stay on the person’s device unless a separate, approved product decision authorises a selected one-time release (for example guest share).

What the Platform does

Obliged-entity staff use one operate desk to run identity and compliance work without turning every colleague into a super-administrator.

  1. Subjects and cases. Open work items for people your organisation must know, with status that stays honest when a provider is offline.
  2. Organisations and screening. Maintain counterparties and screening queues. This demo does not claim a live screening vendor.
  3. Document requests. Compose staggered requests (hard cap 100 per person per organisation), with expiry that auto-declines and dual-side request logs.
  4. Grants and search. Review packs the person granted; search within clearance. Mid-flight staff tier changes snap clearance immediately.

Permission tiers (mandatory)

Every organisation starts with an Admin tier and ships default packs for likely EU AML and KYC entity types (bank, fintech or EMI, crypto-asset service provider, real estate, law firm, gambling, telecom). Admin may define custom tiers in a controlled style similar to Google Admin: dramatic differences in views, clearances, and write abilities.

Trust and security meaning

Security language in LETZZ is deliberate and calm. The product aims for bank-style seriousness without theatrical claims.

  • One device key gates Wallet actions on the phone; recovery restores the same key.
  • Daily unlock prefers Face ID (or available biometry); outbound release refreshes proof of presence.
  • Web authentication may use the phone as authenticator (Path A) or a web authenticator when available (Path B), with honest unavailable states.
  • Local monitoring watches suspicious unlock and recovery patterns without exporting vault contents for analytics.
What this partner hub is. An Alma-gated GitHub Pages simulator with synthetic data. It demonstrates UX honesty and flows. It is not production hosting, not a live Cognito or screening integration, and not a substitute for regulated deployment evidence.

Architecture for builders

Shipping spine today: Letz File monorepo with native Wallet (letzwallet/), Obliged Entity web (platform/web-oe/), shared API (platform/api/), one database process for platform state, and versioned HTTP under /api/v1. Platform Owner web is infrastructure, not a peer product.

Implementation invariants

  • Prometheus Protocol: evidence-led status; honest gated or degraded states; no false completion.
  • No fake integrations: ship real behaviour, a clean unused abstraction, or an explicit unfinished state.
  • No certification theatre: do not claim AML6, eIDAS/EUDI, or ILNAS/QTSP readiness from UI copy alone.
  • CSP baseline on Platform web shells; production must narrow connect-src to the real API origin.
  • Staged release: OE first with observe gates, then Wallet; fail closed or gate honestly when samples are insufficient.

Honesty boundaries (shared)

  • No claim of live AML6, eIDAS/EUDI, or ILNAS/QTSP certification from this documentation or demo.
  • No claim of production Cognito, mesh sync, or unrestricted vault byte export unless an approved decision says otherwise.
  • Demo password Alma is client-side SHA-256 only - partner convenience, not production auth.
  • Language stays professional and suitable for institutional review.
